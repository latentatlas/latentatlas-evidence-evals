# R10 — Intermediate failures and unresolved scope

The primary model is `results/model_v2.json`, generated by
`build_model_v2.py` and evaluated by `model_v2.py`.

The first model evaluator used `arb_interval ** Python_integer`.
With the installed python-flint, an interval crossing zero returned
a nonfinite result under that general power operation. The first
window probe therefore stopped before producing a theorem certificate.
The original `model.py`, `build_model.py`, `probe_window.py`, the
initial data `diagnostics/model_v1.json`, and the failure record
`diagnostics/window_v1_failure.json` are retained. The v2 evaluator
uses repeated multiplication at exact endpoints, with monotonicity
and an explicit zero-crossing rule for even integer powers. No
nonfinite value was replaced by a fictitious finite error bound.

`diagnostics/window_v2.json` is a feasibility probe with T=0.01 and
exploratory radii. The final certificate uses the explicitly dyadic
box recorded in `results/window_certificate.json`. Do not quote the
probe's numerical bounds as the final theorem's bounds.

The plot source first emitted a Python warning about a backslash in
a non-raw caption string. The text was already rendered as intended;
the source was corrected to use a raw string and the figures were
regenerated. `diagnostics/plot_escape_fix.json` records the previous
source hash and figure metadata. The final PNGs are byte-identical
to the images directly reviewed. The old pre-fix source hash is an
identification record; the one-character source version itself is
not a separate frozen file.

The 780 gray chart cells are not failed theorems or known multiple-root
cells. Their uniform critical-point or critical-value tests did not
produce a root count at this subdivision. They remain unclassified.
Colored cells have separate rational verification. A continuous
critical-value criterion and full multiple-root parametrization are
proved on the larger physical box, but a complete numerical partition
of that box is not claimed.

The rational sample checker produces its own tight root boxes. They
can be wider than the generating implementation's tight boxes because
the interval arithmetic and expression grouping differ. Both prove
existence in the same larger uniqueness boxes; no inappropriate
requirement of identical tight bounds is imposed. Published decimal
special-point bounds use the rational checker results.
