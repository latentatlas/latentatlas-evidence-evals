Reproduction now explicitly classifies the exact two known dependency conflicts and rejects any unexpected dependency failure; a subprocess timeout cannot fall through to a later step.

## Analysis/measurement revision before final v02

The full v01 plan completed all26 executions with unchanged frozen code and exit0; records are retained, not added to the final sample. Read-only review during that run identified an outcome-dependent QA gate (expecting baseline V-fail), an unconditional artifact-truth sentence, missing artifact-path truthfulness comparison, and inability to preserve an additional repeated completion as a valid control counterexample. v01 was allowed to finish without changing its frozen code.

Before v02: actual-record validity no longer requires a chosen control outcome; synthetic classifier tests provide known-counterexample calibration. Artifact truthfulness is separately reported and native read bytes/path are corroborated. Additional completion invocations remain individually identified and immediately captured instead of aborting due to a duplicate semantic role. An explicit `--receipt-fault bypass` diagnostic disables only the local receipt at the old-redelivery phase, to test that a real extra admission is evidence-valid but fails the duplicate-prevention outcome. This injected diagnostic is outside the unchanged26-cell main design, not a natural incident or a selected confirming observation. All changes and the reporting/auditing sources are frozen afresh before the final v02 matrix and its fresh-environment replication.

Native write-result timestamps follow write return and a hash read, so they are not exact physical commit instants. Final v02 represents observed effects by [native attempt, observed result] intervals. An interval crossing the operator request cannot establish which side the byte visibility occurred on; R is unknown unless another definitely late effect establishes failure. Completion-observation counts remain labelled as such. V still uses actual native entry under the origin lock. New-work latency is described as admission-to-terminal-retrieval, not active compute time.
