# Stop Scope receiver experiment reproducer

Can stopping a source process prevent work already accepted by a separate receiver? This package reruns one bounded Stop Scope mechanism experiment. It includes the control implementation, a separate record auditor, synthetic fixtures, a recorded example matrix, and tests.

The experiment uses real local processes and file writes. All actors in this package are programmed. It makes **no model calls**, needs **no account or API key**, and installs **no third-party dependencies**. It is not the live-model pilot or a control integration for arbitrary agent systems.

## Check the recorded evidence

Use Python 3.10 or newer on a POSIX system (macOS or Linux intended; see `REPRODUCTION_ENVIRONMENT.json` for what was actually tested). From this directory:

```sh
python3 -B verify.py
python3 -B -m unittest test_receiver test_portable
```

The first command checks the release hashes, recomputes the supplied 16 conditions, compares raw effect receipts and actual file bytes, and checks 18 I/N report pairs against their healthy references. The second runs the preserved auditor checks and packaging checks. Neither command starts an experiment or contacts a provider.

## Run a fresh experiment

Run these commands from this directory; choose different `local-` names if they already exist:

```sh
python3 -B run.py --smoke --out "$PWD/local-smoke-v01"
python3 -B verify.py --run "$PWD/local-smoke-v01"
python3 -B run.py --out "$PWD/local-matrix-v01"
python3 -B verify.py --run "$PWD/local-matrix-v01"
```

Run the full matrix only after the smoke verification succeeds. Old output directories are never overwritten. The source process is deliberately terminated in stop conditions; the receiver and observer are separate processes. Each experiment writes only into its new output directory. Child processes deny network connections; the source code contains no provider client.

## Read the result

O is the old task, C is later work from the same old origin, I is independent work, and N is new human-authorized work. The four controls are a healthy reference, source-process termination, cancellation of the current receiver job, and revocation of the old origin at the receiver.

| Control before O writes | O final file | Later C file | I and N files |
| --- | --- | --- | --- |
| Healthy reference | Present | Present | Present |
| Source termination | Present | Present | Present |
| Cancel current O job | Absent | Present | Present |
| Revoke old origin | Absent | Absent | Present |

When O has already written but its worker has not returned, every normal control retains that completed O file. Cancellation/revocation is not rollback. The matrix contains three timing cuts and four controls, plus four separate fault checks: an ineffective revocation, overbroad revocation, a missing receipt, and wrong task content.

Expected verification: **12 main conditions and 4 fault checks; 15 recorded and 1 intentionally `needs_review`**. The missing-receipt condition must keep the visible disk effect while withholding trusted attribution. Ineffective control, collateral damage, and wrong content remain measured outcomes. Unexpected outcomes are reported for review, not discarded.

Start with `RESULTS.json` and each condition's `AUDIT.json`. Follow the evidence into `coordinator.jsonl`, `source.jsonl`, `receiver.jsonl`, `observer.jsonl`, `PROCESS.json`, and the actual `store/` files. `COMPLETION.json` binds each inventory to hashes. PID, UUID, timestamps, and whole-run hashes naturally change on a rerun; the expected mechanism outcomes are compared, not those incidental identifiers.

## Provenance and limits

The receiver, source, observer, journal helpers, auditor, and original protocol are copied byte-for-byte from `f07_receiver_process_v01`. `PROVENANCE.json` identifies every original source hash. `provenance/portable-run.diff` shows the driver changes: local-history dependencies become packaged fixtures and package-relative protection; POSIX/version guards are added. The episode implementation is unchanged. `test_receiver.py` only changes the path of its recorded test fixture.

The frozen O/I/N payloads came from a prior live healthy episode; C came from its programmed follow-up. They are replayed here, not generated by a model. `fixtures/SOURCE_EXCERPT.json` provides a selected provenance excerpt and source hashes; it is not the complete historical live transcript. The supplied example is a **new provider-free reproduction**, not a modified historical record.

This slice uses trusted fixture identities, fixed create-only file paths, one host, and one synthetic development input. It does not test arbitrary tools, malicious local processes, durable queues/restart, or model resistance. Clean relocation on the author's host is not independent reproduction. New catalogue acceptances: zero.

## Troubleshooting and safety

- Use `-B` as shown so bytecode caches do not alter the sealed package inventory.
- A reused output name is an error: pick a fresh name; do not erase an earlier attempt.
- Hash mismatch, unexpected files, RPC/worker timeout, or an outcome difference needs inspection. Preserve the failed attempt; do not silently rerun until it passes.
- Windows is rejected before the experiment because the source-termination check assumes POSIX SIGTERM.
- No `pip install`, model credentials, browser sign-in, payment, or external publication is part of this example.
- Review fresh logs before sharing them: an unexpected Python traceback can contain your local path. The supplied release is separately scanned for the author's local paths and credentials.
